# Site público e Festa

- Public website lives only in `src/site/` under the `.site-publico` wrapper; its tokens/fonts are scoped there and it never imports or edits system layouts/shared UI. Site lives at the root; staff dashboard is `/equipe` (legacy `/site/*` redirects). Internal site links use `sitePath()` from `src/site/config.ts`. Public /corrida and /store render inside `src/site/ComercioPublico.tsx` (scoped overrides in `comercio.css`); the portal store reuses the same pages without that shell. Why: keep the production system's dark theme and flows untouched.
- Google tag/Meta Pixel load only on public routes via `src/site/RastreamentoPublico.tsx` (route list, consent, events in `src/site/rastreamento.ts`), never in index.html. Why: no ad tags in staff/student areas and LGPD consent first.
- Public website photos use CDN pointers in `src/assets/fotos` and a scoped photo registry with intrinsic dimensions; photo frames reserve their ratio and retain red corners. Why: reuse uploaded media without layout shifts or leaking styles into the system.
- Team member photos are looked up by exact name via `fotoEquipe()` in `src/site/fotos.ts` wherever a person appears. Why: one upload updates every page.
- Festa: config holds editorial; insert trigger computes new totals; settlement and edits keep historical totals. Why: consistent pricing.
- Festa deadline is shared by frontend config and confirmation/PIX code through the pure `_shared/festa-prazo.ts` module; no deadline gate on settlement. Why: keep opening and PIX expiry consistent without rejecting existing payments.
- Fotos de eventos (reconhecimento facial): AWS Rekognition só nas funções `fotos-evento-*` via `_shared/rekognition.ts` (SigV4 próprio); regras puras em `_shared/fotos-evento.ts`; coleções sempre "fortem-…"; bucket `fotos-eventos` privado só com URL assinada; público nunca lê as tabelas; selfie só em memória; gerir = admin/coordenador, moderar = + professor; aprovação e envio da equipe indexam na hora via `_shared/fotos-evento-indexacao.ts` (o painel só retoma o que sobrou); galeria antiga `festa_fotos` fica separada. Por quê: biometria (LGPD) e chave AWS restrita ao prefixo.
- Página pública de fotos (/10anos/fotos) fica em `src/site/fotosEvento/` com CSS escopado em `.fotos-evento`, fora do rastreamento de anúncios; usa o evento de slug fixo `10anos`, a mesma chave Turnstile do /planos (`planos_turnstile_*`) conferida a cada busca/envio, e a capa vem só de `eventos_fotos.capa_foto_id` (aprovada). Por quê: página biométrica sem tags de anúncio e sem foto genérica.
- Molduras das fotos da festa: layout puro em `src/lib/molduraFotos.ts` (lista de elementos, áreas seguras, regra de cor, P&B por pixels) e desenho/entrega em `src/site/fotosEvento/moldura.ts` (canvas a partir do original assinado, JPEG 90, Web Share com arquivo no celular, senão download/zip); a prévia exibida é o próprio arquivo gerado. Por quê: o que o convidado vê é exatamente o que salva, e o layout é testável sem navegador.
